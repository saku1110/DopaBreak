# DopaBreak オンボーディングCVR改善案

2026-09-07。現行ソースの静的レビュー。実機画面・実ユーザーのファネル・配信ビルドは未確認。以下は改善仮説であり効果の実測ではない。製品コードは変更していない。

## 現状

- `ios/DopaBreak/OnboardingFlow.swift` の18ステップ: welcome → selfCheck → quizAimless → quizRegret → quizResult → recovery → chooseApps → goalSetup → chooseMode → preview → whyScience → permission → notificationGuide → lockScreenCheck → lockThemePick → prePaywallSummary → blockSetup → ready。目標なしではlockScreenCheck、Freeまたは非ブロックモードではblockSetupを省略する。
- 主課金導線は16番目のprePaywallSummary。複数対象やProモード選択でも、それ以前に課金画面が出る。
- previewは説明・キャラクター変化・選択肢の見本が中心。オートメーション設定前に操作できる短いデモへ発展させる余地がある。
- ロック画面への目標反映、テーマ選択、損失時間の個別推計、課金前サマリーは既にある。これらを未実装として重複提案しない。
- 完了ステップ・課金画面・購入等のイベントはローカルJSONへ保存。画面表示イベント、実験割付、初回コホートを含む全ユーザーファネルは今回確認できていない。RevenueCatの購入サーバ通知だけから画面離脱は把握できない。

## 優先順

1. **主課金導線までの外部操作を減らす実験。** 通知許可・実際のロック画面確認を後へ移す。テーマと目標のアプリ内プレビューは価値訴求として残せる。ショートカット設定は実際の成功体験を生むため、まずは維持し、それ以外の移動を先に比較する。次に「短いアプリ内デモ→課金→ショートカット設定」の順序を別実験で比較。課金を前へ動かす場合も購入前に設定が必要と伝え、購入/無料選択直後に設定へ案内する。設定完了率・D7継続が下がるなら採用しない。
2. **途中での課金割り込みを整理。** 最初は最も減らしたい1アプリで体験させる案。複数アプリ・Proモードは希望として保存してサマリーでPro便益に結び付ける案も比較する。Freeへ進む場合は有効になる1アプリとモードを明示して確定する。価値体験前の即時課金が有効な可能性もあり、一律に廃止とはしない。
3. **プレビューを短い操作デモへ。** 選んだSNSを開こうとする→理由選択/一呼吸→「開かない」をアプリ内で体験。デモと明記し、本番の回数・節約時間へ加算しない。デモの長さは実測で調整。
4. **目標入力を1タップでも完了可能に。** 現状は自由入力・複数目標管理・スキップがある。読書/勉強/睡眠などの例から選択して編集可能にし、最初は1目標を中心にする。目標の意味づけは維持し、キーボード負担を減らす。
5. **冒頭の損失訴求は維持しつつ、後半は行動とPro固有の価値へ。** 人生年数の不安を繰り返す案と、「選んだ複数SNSをまとめて対象に」「集中/就寝時間のブロック」「選んだProデザイン」を回答に応じて示す案を比較。Freeの一呼吸をPro限定に見せない。科学的背景は要点＋詳細へ整理できるが、研究の対象・限界は省かない。

## 実験と判定

- 主指標は初回起動ユーザーを分母にした一定期間内（例D35）の有料転換率。早期指標として課金画面到達率・トライアル開始率、ガードレールとして設定完了率・初回実介入率・D7継続・返金を確認する。トライアル経由と直接購入を分ける。
- 計測候補: 初回オンボーディング開始、各画面表示/完了/スキップ、アプリ外への移動と復帰、課金placement、デモ完了、手動設定チェック、実際の対象アプリからの起動、トライアル開始、課金成立。手動チェックを動作確認成功として集計しない。
- 同じユーザーの反復表示を重複人数に数えない。新規/再表示、国・流入元・ビルド・トライアル適格性を分ける。検証端末とSandboxを本番指標から除外。
- まず計測と非破壊的な再表示用QA導線を整え、最初の比較は通知許可・実ロック画面確認の後置へ絞る。同時に文言・価格・トライアル期間まで変えない。外部分析追加は既存の端末内保存の説明と整合する設計が別途必要。
- 改善率の予測値やスキル中の他社の改善率は流用しない。サンプル数は基準CVRと検出したい差から決め、少人数の変動で勝敗を断定しない。

## 追加確認: Proの説明と体験

- 説明項目は揃っている。PaywallView.featureListは対象数制限解除、完全ブロック、解除待ち30秒、毎週の予定2つ、就寝中ブロック、ロック画面デザインを表示。
- 購入前体験はテーマが最も具体的。本人の目標でProテーマをプレビューし、未購入時は保留、Proが必要と表示する。
- 複数対象とProモードは選択時に課金画面へ遷移。ブロック設定はProかつ対象モードの場合に主課金案内後へ配置され、未購入ユーザー向けのブロック操作デモではない。
- 一呼吸の操作デモはアプリの基本価値体験であり、Freeでも使えるため、それだけでProの体験が十分になるとは評価しない。
- 次回の最小改善候補: 既存モード選択/サマリー内で「勉強中は対象SNSを開けなくする」「就寝時間に自動ブロック」など生活場面とPro便益を対応させる。説明画面や権限要求を追加せず、必要ならブロック画面のアプリ内見本を使う。審査中の提出物は変更しない。
- 判定は静的な設計評価であり、Pro説明の不足が実際の離脱原因かは未検証。
