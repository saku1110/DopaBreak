作成: 2026-07-02（オーナー指摘「介入は内部用語」「アプリを守るは意味不明」を受けて新設）
**役割: ユーザーに見えるすべての文言はこのドキュメントが正本。実装（Fable/Codex/Opus）はここから転記のみ。新画面を実装するときは、先にここへ文言を追加してから実装する。**

## 0. 文言の原則

DopaBreakは **SNS依存・ドーパミン中毒を軽減するアプリ**。文言は「自分の悩み（無意識にSNSを開いて時間を溶かす）が解決できる」と一読でわかる、具体的で自然な日本語にする。

| 層 | 語彙 |
| --- | --- |
| **問題の言葉**（ユーザーの自己認識） | SNS依存 / ドーパミン中毒 / 無意識に開く / 時間を溶かす / ダラダラ見て後悔 |
| **解決の言葉**（機能の説明） | 一呼吸をはさむアプリ / 完全にブロックするアプリ / 止める強さ / 開こうとした / 開かずに我慢 / 一呼吸 / 見たあとの気持ち / 取り戻した時間 / 戻る先（＝目標） |
| **禁止** | ①内部用語: 介入・再介入・シールド・セッション・リフレクション（UIでは「見たあとの振り返り」）②医療表現: 治療・治る・依存症の診断 ③対象が曖昧な表現: **「アプリを守る」「あなたを守る」**（何を守るのか不明）④過度な口語・スラング |

- 見出し・短い表示文: 句読点を使わない（改行と体言止め。グローバル規則）。本文・説明文: 通常の句読点OK。
- トーン: 責めない・禁止しない・命令しない。「〜しましょう」より事実と選択肢の提示。
- オンボーディングの全文言は [doc07](./07_onboarding_design_lifefocus.md)、通知・Live Activity文言は [doc06 §9](./06_screen_design.md)、ペイウォールは本書§5。

## 20. ロック画面の掲出確認（2026-07-25 新設・オーナー指示）

## 21. 全画面コピー精査（2026-08-28）

アプリ本体、オンボーディング、開く前の一呼吸、設定、ペイウォール、通知、シールド、ウィジェットの日本語を一括精査した。以後は次を全画面共通の基準とする。

- 見出しとボタンは短く保ち、原則として句点を付けない。説明文は体言止めや語句の羅列で終わらせず、主語・動作・結果が分かる文章にする。
- 機能名だけを説明せず、「何をすると」「次に何が起きるか」「ユーザーに何が残るか」の順で示す。

- `Localizable.xcstrings` の日本語を表示文言の正本とし、Swiftの `defaultValue` も同じ内容へ同期する。キー名と位置指定子は変更しない。

## 22. 3言語のネイティブ品質基準（2026-08-28）

§21の日本語精査を `humanizer-jp` の基準で再確認し、英語は米国向けモバイルUI、韓国語は韓国向けモバイルUIとして全String Catalogを見直した。直訳で語順だけを置き換えず、各言語で同じ操作と結果が自然に伝わることを優先する。

| 意味 | ja | en-US | ko |
| --- | --- | --- | --- |
| 開く前に立ち止まる体験 | 一呼吸／開く前に一呼吸 | Pause／Pause before opening | 숨 고르기／열기 전에 숨 고르기 |

## 23. 改行と動的な数値表示（2026-08-28）

全画面で、表示幅に合わせた自動折り返しと、文言側で指定する強制改行を分けて扱う。

- 強制改行は、段落の切り替え、見出しの意味の切れ目、法律文の文区切りにだけ使う。端末幅1種類の見た目を整えるためには使わない。
- 数値と単位は同じ表示要素にする。`16` と `回`、`16` と `times`、`16` と `회`を別要素にせず、単位だけが次の行へ残る状態を禁止する。
- 動的な集計値は「数値＋単位」と説明ラベルを分ける。数値を先に認識できる階層にし、VoiceOverには自然な全文を別途渡す。
- 横並びの指標は、文字サイズや翻訳が収まらない場合に縦積みへ切り替える。文字を一律に小さくして収めない。
- 既存の強制改行はオンボーディングの段落、ペイウォール法定文、複数行見出しだけを許可対象とし、新規追加時は5つのString Catalogを横断する回帰テストへ登録する。
