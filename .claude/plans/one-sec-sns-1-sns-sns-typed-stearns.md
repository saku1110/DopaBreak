# LifeFocus 画面モック作成計画

## Context（なぜ作るか）

competitor「one sec」を分解した結果、one secは「SNSを開くまでの遅延・摩擦」だけで勝負しており、これは激戦区かつコモディティ化する機能。本プロジェクト（LifeFocus / 仮称）は「SNSを断ち人生を取り戻す」コンセプトで、**ロック画面ウィジェットに人生の目標・1年の目標を常時表示し、SNSを開く瞬間に一呼吸＋意図確認＋必要時間だけ開放する**アプリ。

既存資産：
- `docs/` に事業〜画面設計が一式。ただし **doc06（旧GoalGate：目標/アファメーション入り）と doc07・README（最新LifeFocus：目標を全削除）が矛盾**。
- `output/mockups/lifefocus_onboarding/` にオンボ7画面のHTML品質モックが完成済み（黒×集中リング）。ただしWelcome単体はリングが見出しに被り可読性が低い。
- コア/介入/ウィジェット/ペイウォールは未作成、もしくはGemini生成のラフのみ（品質不足）。

このタスクのゴール：**矛盾を解消した上で、統一トーンで全画面の高品質モック画像を作る。**

## 確定した方針

### 1. 機能の主従（Q1の決定）
- **目標表示＝ヒーロー（看板/マーケ主役）、SNSゲート＝エンジン（日次の実用機能）** の二層構造。
- 理由：アプリブロッカー市場は飽和（one sec等）。「SNS断ち×人生の目標×ロック画面」の掛け合わせは日本語市場で手薄＝ASO/差別化/女性20万フォロワー送客に最適。モートは感情設計側にある。
- **目標は軽量に留める**：ヒーロー目標1つ＋1年目標1つのみ。ロック画面ウィジェットと介入時にだけ表示。タスク管理・期限・チェックリスト・複数タスク・引き寄せコピーは入れない（doc07の警戒を尊重）。
- → doc06とdoc07の中間。「目標は戻すが、軽量・感情訴求のみ」。

### 2. 範囲（Q2の決定）
- **全画面を1つの統一トーンで作り直し**（既存オンボ7画面も含む）。

### 3. ビジュアル（Q3：3トーン比較してから確定）
- 先に **代表2画面 ×3トーン＝6枚の比較モック** を作って提示 → ユーザーがトーン確定 → 全画面を本番作成。
- 比較する3トーン：
  - A. 黒×集中リング継続＋可読性改善（リングを余白に退避）
  - B. ミニマル（Linear/Notion風・ダーク基調＋1アクセント・余白とタイポ）
  - C. 明るい朝（Sunrise・白〜淡色基調・希望感・介入時のみ暗転）
- 比較に使う代表2画面（ブランドを最も背負う＝差別化が出る画面）：
  - **ロック画面ウィジェット**（＝最大の差別化。人生目標が常時見える）
  - **介入の瞬間**（一呼吸→目標カード→意図確認。signature screen）

## 生成方法（Gemini 画像生成）

- **Gemini 画像生成（`gemini-3.1-flash-image-preview` / Nano Banana Pro）**。`google-genai` SDK 1.47.0、`GOOGLE_API_KEY` 設定済み。
- プロンプトは **JSON形式で構造化**（image_type / style / layout / colors / texts / mood / size）。日本語UI文字はGeminiが崩しやすいため、テキストは短く・少なく指定し、世界観とレイアウト優先。
- 解像度：縦長スマホ画面比率（9:19.5相当）。出力後 Pillow で 1206×2622 にリサイズ/パディング統一。
- デザイントークンは doc07 を踏襲（Void Black #05070D / Aura Violet #8B5CF6 / Breath Cyan #70E1FF / Ritual Gold #F8D477 / Recovery Green #55D6A0 / Mist #9AA8C7）。トーンB/Cは派生パレット。
- SNS実ロゴは使わず汎用アイコン（ライセンス回避。doc07準拠）。
- 生成スクリプトはスクラッチパッドに置く。

### 既知の制約（重要）
- Geminiは日本語テキストの精度が低い（文字化け・潰れ）。**実装用の精密UIモックには不向き**で、本用途は「トーン・世界観の比較検討」と割り切る。精密版が必要になったら別途HTML/CSS方式に切替。

## 出力先

## 進め方（実行フェーズ）

- **Phase A**：レンダリング環境構築 ＋ 代表2画面×3トーン＝6枚生成 → ユーザーに提示しトーン確定。
- **Phase B**：確定トーンで全22画面を生成。命名は `NN_screen.png`＋俯瞰ボード。
- **Phase C**：READMEと、必要なら設計書（doc06/07）の方針整合メモを更新（目標ヒーロー軽量版に統一）。

## 検証

- 全PNGが1206×2622で出力されていること（`sips -g pixelWidth -g pixelHeight` で確認）。
- 主要画面を実際に開いて目視：見出しの可読性（装飾が文字に被らない）、CTAが下部44pt以上相当、日本語の改行・文字切れ無し、トーン/トークンの一貫性。
- 介入フローが「一呼吸→目標→意図→時間→結果」で筋が通っているか、ロック画面ウィジェットで目標が主役になっているかを確認。
