# BUILD SPEC: 炎ステージ（守るほど育ち、青へ至る火）

> **⚠️ 実装不可（2026-08-14）**: 前提の炎ビジュアルがオーナー決定「火は全て削除」で撤去されたため、本構想は現状実装できない。再開にはオーナーの再判断が必要。詳細: `.claude/specs/design-decisions.md` 2026-08-14。

ステータス: 仕様確定待ち（オーナー発案 2026-08-07・方向性承認済み）
実装開始条件: 種火v2（`BUILD_SPEC_GOAL_EMBER_V2.md`）のCodexレビュー完了とコミット後

## 背景・目的

炎はこれまで演出（介入の一呼吸・目標画面の種火）だった。これを**状態を持つ仕組み**へ昇格させる。
守れた日が続くほど火が育ち、21日で青い炎に至る。Forestの木（枯れる賭け金）と同じ
損失回避を、日次の習慣レベルで働かせて継続率を上げる。

オーナー指示の原文: 「我慢するたびに火がついて最終的には青い炎になるとか演出入れて継続させる」

## 設計原則（先に決める。ここが本体）

| # | 原則 | 理由 |
|---|---|---|
| 1 | **火は絶対に消えない**。最低は種火。死んだ炉は一度も見せない | ストリーク羞恥による削除（Duolingo型の失敗）を構造的に防ぐ |
| 2 | **開こうとしなかった日は下げない** | 誘惑ゼロの日は最良の日。罰したら本末転倒 |
| 3 | **復帰は速い**。降格の翌日に1回守れば即1段戻る | 「取り戻せる」が継続の燃料。挫折→放置の連鎖を切る |
| 4 | 降格の演出は静か。火が細る様子をアニメーションで見せつけない | 負けた直後のユーザーに追い打ちをかけない |
| 5 | 課金でステージをロックしない | 火は無料のリテンションエンジン。収益は継続経由で取る |

## ステージ定義

| level | 表示名(ja) | 到達条件（守れた日の連続数） | 視覚 |
|---|---|---|---|
| 0 | 種火 | 初期状態 | intensity低・暖色 |
| 1 | 灯った炎 | 1日 | 通常の暖色 |
| 2 | 安定した炎 | 3日 | 大きく安定・火の粉標準 |
| 3 | 大きな炎 | 7日 | さらに大きく・火の粉増量 |
| 4 | **青い炎** | **21日** | パレットが青系へ反転する特別状態 |

- 表示名はUI文言ルールに従いユーザー語彙で（「介入」「シールド」等の内部用語禁止）。
  en/koは実装時にhumanizer各ゲートを通す
- 「熱いほど静かに青く燃える」を到達演出のコピー種として保持（表示時はディスプレイコピー規則適用）

## 日次判定ルール

1日の終わり（またはその日初回のアプリ起動時に遡って）に、その日を3値で判定する:

| その日の実績 | 判定 | ステージへの効果 |
|---|---|---|
| 守り ≥ 1 かつ 守り ≥ 負け | 守れた日 | 連続日数 +1（到達条件に従い昇格） |
| 負け > 守り | 崩れた日 | 1段降格（level 0が下限）。連続日数はリセットせず「保留」にする |
| 開こうとした記録なし | 静かな日 | **変化なし**（連続日数は維持。原則2） |

- 「守り」= 介入フローで開かずに戻った回数（既存の記録を使う。новых計測は増やさない）
- 「負け」= 介入フローを通過してターゲットアプリを開いた回数
- **復帰ルール**: 崩れた日の翌日に守り≥1なら、降格した1段を即時回復する（原則3）
- 同日内の再判定はしない（日をまたいだ時点で確定）。タイムゾーンはデバイスのカレンダーに従う
- 連続日数の「保留」: 崩れた日はカウントを0に戻すのではなく、翌日の復帰で継続扱いにする。
  2日連続で崩れたらリセット

## 表示場所（MVPスコープ）

| 場所 | 内容 |
|---|---|
| ホーム | 現在ステージの炎を常設表示（炉）。タップでステージ進行表 |
| ステージ進行表 | 5段階の一覧。現在位置と「あと◯日で次の炎」を明示。**青い炎のシルエットを最初から見せる**（見えない目標は存在しないのと同じ） |
| 介入の一呼吸 | 呼吸の炎を**その人の現在ステージのパレット・強度で描く**。青い炎の人は誘惑の瞬間に自分の青い炎を見る（損失回避を選択の瞬間に働かせる。この仕様の核） |
| 昇格演出 | 昇格した日の初回ホーム表示で一度だけ祝福（既存の完了画面の祝福トーンに合わせる）。青い炎の初回到達のみ特別演出 |
| 目標画面の種火 | 変更なし（火を灯す前フリとして現状維持） |

MVP外（バックログ・実装しない）: ウィジェット/Live Activityへのステージ反映、青い炎到達のシェアカード（SNS共有によるオーガニック獲得。post-MVPで検討）、ロック画面面への反映。

## シェーダ変更（聖域の意図的解除）

`Shaders/Flame.metal` は種火v2まで「無変更」を不変条件としてきた。本件は**意図的に解除**する。
ただし変更は最小限に限定する:

- `float bluePalette`（0=暖色, 1=青系）uniformを1つ追加
- 既存の暖色ランプ（darkRed→emberRed→…→whiteCore）と対になる青系ランプ
  （deep navy→blue→cyan→白青コア）を定義し、`mix(warm, blue, bluePalette)` で合成
- 火の粉の色も同係数で追従
- 既存の呼び出し（介入・種火）は `bluePalette: 0` で**ピクセル単位で従来と同一出力**であること
  （回帰の受け入れ条件。FlameSnapshotCapture方式で撮影比較する）
- level 0〜3はintensity・火の粉量の差で表現し、パレットは使わない。青はlevel 4専用

## データモデル

- 既存の介入結果記録から日次の守り/負けを集計する（新規イベント計測は追加しない。
  既存の記録粒度で不足する場合のみ、日次集計テーブルをDopaBreakCoreに追加）
- `FlameStageEngine`（DopaBreakCore・純関数）: 日次実績列 → 現在level・連続日数・次段までの残日数。
  `Date`直参照禁止（テスト可能にするため現在日時は引数注入）
- 永続化はSettingsStore/既存ストレージの流儀に従う
- テスト: エンジンは全遷移（昇格・降格・復帰・保留リセット・静かな日・境界の21日・下限0）を
  網羅。カバレッジ80%以上、遷移ロジックは実質100%を狙う

## 受け入れ基準

1. 21日間の守れた日で青い炎に到達する一連をエンジンテストで再現できる
2. 崩れた日→翌日1守りで即復帰することをテストで固定
3. 開こうとしなかった日にレベルが動かないことをテストで固定
4. `bluePalette: 0` の描画が現行シェーダとピクセル一致（キャプチャ比較）
5. 介入の一呼吸がユーザーの現在ステージで描かれる
6. 進行表で「あと◯日」と青い炎の存在が最初から見える
7. 全表示文言がユーザー語彙・ディスプレイコピー規則・3言語対応（en/koはhumanizerゲート通過）

## 実装順序

1. `FlameStageEngine` + テスト（DopaBreakCore）
2. シェーダの青パレット + 回帰キャプチャ
3. ホームの炉 + 進行表
4. 介入への現在ステージ適用
5. 昇格演出・コピー・l10n
6. 全体検証（/verify相当）

実装は現行体制（Codex gpt-5.6-sol effort max、レビューOpus5）。Codex使用上限中はOpus5実装+Codexレビューのフォールバック。
