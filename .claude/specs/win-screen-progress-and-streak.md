# 開かなかった画面: 次の節目までの進捗と連続記録

決定日: 2026-09-01（オーナー指示・実機で下部の余白過多を確認）

## 解決する問題

実機で画面下半分が空いている。要素を上へ詰めて下を捨てる配置になっている。
情報としても「貯まっている額」はあるが「目標額」がなく、貯金の実感が半分しか出ていない。
節目でクラッカーが出るのに、その節目が事前に見えていない。

## 実装

### 1. 次の節目までの進捗

累計の下に、次の節目までの距離とバーを置く。

```
6時間ぶんまで あと32分
━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 37%
```

- `ReclaimedTimeMilestone` に **次の閾値を返す** API を追加する
  （`highestReached` の対になる `nextThreshold(after:)` 等）。閾値の定義を二重に持たない。
  段階は既存と同じ 3,600 / 21,600 / 43,200 / 以降は86,400の倍数。
- 進捗率は「直前の節目 → 次の節目」の区間で求める。累計0からの比率にしない
  （そうすると日数段階で常にほぼ満杯に見える）。
- 残り時間の書式は既存の `ReclaimedTimeFormatter` を使う。新しい書式を作らない。
- 文言は単位の翻訳を主役にする。時間段階は「6時間ぶんまで」、日数段階は「まる2日ぶんまで」。
- **節目バナーを出している回はこのブロックを出さない**（今まさに到達した直後に
  「あと◯分」を出すと祝いが濁る）。

### 2. 連続記録

- `StatsService.consecutiveDaysWithCancellations(endingOn:)` を使う。新しい集計を作らない。
- 表示は「%lld日連続」。
- **0日のときは出さない。** 「0日連続」は罰になる。1日以上のときだけ表示する。
- 「今日 N回 開かなかった」と同じ行に横並びで置く。

### 3. 縦方向の配分

- 情報を足すだけでは余白は消えない。要素間の間隔を配分し直し、下端に大きな空白を残さない。
- 目標5件のときは3件のときより詰まるため、件数に応じて間隔を調整する。
- 目標を隠す方向で逃げない。キャラクターと目標カードは同時に表示できること。

## 今回やらないこと

- **直近の満足度の内訳表示。** 満足度画面自体の表示順序と要否をオーナーが検討中のため保留する。
- 週次の推移グラフ（統計画面の役割）。
- 「8分＝◯◯1回分」等の換算（恣意的で効果断定に寄るため不採用）。

## 制約（変更禁止）

- 取り戻した時間は推定値。効果断定へ言い換えない。
- 表示コピーに読点を入れない。句点を打たない。体言止めを基本にする。
- 装飾用の英語eyebrowを使わない。内部用語をUIに出さない。
- Swift側 defaultValue と Localizable.xcstrings を完全一致させ ja/en/ko を揃える。
- 既存の増分カウントアップ・節目バナー・紙吹雪・Reduce Motion対応を壊さない。
