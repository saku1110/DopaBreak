# DopaBreak オンボーディング画面設計

作成日: 2026-06-27 / 改訂: 2026-07-02（確定方針「目標ヒーロー軽量版」反映・損失顕在化クイズフローの正式化・v2モックと整合）

## 1. 方針

DopaBreakは、SNS依存を更生して人生に集中するためのアプリである。ただし、ユーザー向け文言では「依存」「更生」を強く言いすぎない。恥や罪悪感ではなく、**現実に戻る、集中を取り戻す、無意識を止める** という言葉を使う。

オンボーディングの目的は、機能説明ではない。ユーザーに以下を完了させること。

1. 自分がSNSを無意識に開いていると認識する。
2. 止めたいSNSを1つ以上選ぶ。
3. 開く前の介入がどう効くか理解する。
4. Screen Time権限を許可する。
5. 最初のブロックルールを有効化する。
6. SNSを使った後に、満足感を短く振り返る設計だと理解する。
7. Live Activity（ロック画面カード）で戻る先が毎日表示されることを理解する。

## 2. 入れないもの / 入れるもの（2026-07-02 確定）

以下はアプリ全体に入れない。

- アファメーション
- 今日の一歩
- 複数タスク
- 期限
- チェックリスト
- リマインダー
- プロジェクト管理
- ビジョンボード
- 引き寄せ訴求

**入れるもの（軽量目標・確定）**: オンボーディングでは最初の目標を1件だけ任意入力できる。完了後はフラットリストとして管理し、Freeは1件、Proは複数件を保存できる。

- 種類ラベルや期限は付けず、人生の方向性を表す短い目標を1件入力する（例: 英語で仕事ができる自分になる）。
- 表示先はLive Activity（フル文言）・ホームウィジェット/Dynamic Island（短縮表示名）・介入時のみ。タスク管理画面にはしない。
- オンボーディングでは O-04 Goal Setup として1画面・任意入力（スキップ可・後から設定可）。

## 3. デザイン原則

### トーン

強制ではなく、冷静な自己制御。

最新モックでは、黒背景、余白、強いタイポグラフィ、直線的な計測バーで「深く集中に入る」感覚を出す。アファメーション、願望実現、潜在意識などのコピーには寄せない。円形の装飾、魔法陣のように見えるリング、神秘的な図形は使わない。

使う言葉:

- SNSを断つ
- 人生に戻る
- 無意識スクロール
- 本当に今必要ですか
- 必要なときだけ、意図して開く
- 現実に集中する
- 集中を取り戻す

避ける言葉:

- あなたは依存しています
- 意志が弱い
- 失敗
- 治療
- 願いが叶う
- 潜在意識

### 心理学的訴求

他のScreen Time系アプリを使っても続かなかったユーザーに刺すため、オンボーディングでは「制限するアプリ」ではなく「開く前の自動反応を止めるアプリ」として伝える。

| 心理原理 | ユーザーの本音 | 訴求への変換 |
| --- | --- | --- |
| 習慣ループ | 気づいたら開いている | 開く瞬間に止まる |
| 実行意図 | 開いた後では遅い | SNSを開こうとしたら一呼吸する |
| 摩擦設計 | 制限を解除してしまう | 解除より前に理由確認を入れる |
| 自己決定感 | 強制されると反発する | 自分で対象SNSと強さを選ぶ |
| 自己モニタリング | 何回開いたか自覚がない | 今日何回目かを見せる |
| 自己観察 | SNS後に満たされたか覚えていない | 見た後の満足感を記録する |
| 恥の回避 | 意志が弱いと思いたくない | 意志ではなく設計の問題として扱う |

コピーの基本方針:

- 「意志が弱い」ではなく「SNSは反射で開けるように作られている」と伝える。
- 「ブロックする」より「開く前に選択を取り戻す」と伝える。
- 「全部やめる」より「一番開くSNSから始める」と伝える。
- 「厳しく制限する」より「解除しない強さで始める」と伝える。
- 「SNSは悪い」ではなく「見た後の自分の感覚を見える化する」と伝える。

## 4. オンボーディング構成（2026-09-20確定・目標から始めるv3）

最大11画面。以下の順序を現行仕様とし、§5以降に残る旧画面の詳細より優先する。

| 順序 | step | 内容 |
| --- | --- | --- |
| 1 | goalSetup | SNSの代わりに何を進めたい？／目標1件必須・例文選択・後で追加変更可 |
| 2 | chooseApps | 止めるアプリを選ぶ |
| 3 | selfCheck | 利用時間の自己申告（既存の選択肢を維持） |
| 4 | scrollRegret | 目的のないスクロールと後悔を1問・1回答に統合 |
| 5 | lossRecovery | 人生の損失時間と回復の推計を同じスクロール画面に表示 |
| 6 | chooseMode | 2026-09-26 オーナー指示: Pro（一呼吸＋完全ブロック）を上に置き、おすすめ・初期選択にする。無料の方は「無料」の印のみ。無料トライアルの表記はこの画面に出さない（ペイウォールだけ）。選択を保存し、ここではペイウォールを出さない |
| 7 | permission | 対象アプリを開き一呼吸→理由→winを体験。S5の完走・再提示抑止とS6の目標表示を維持 |
| 8 | notificationGuide | 体験後に通知案内とOS許可 |
| 9 | prePaywallSummary | 目標・選択プランの要約→ペイウォール。Deep Focus選択時は開始の文脈を表示。CTAは現行文言を維持 |
| 10 | blockSetup | Proのブロックモードを設定。権利未確認時も表示し、Free確定または通常モードなら省略。「あとで」でモードを降格しない |
| 11 | ready | 完了 |

- welcomeの世界観は目標画面冒頭の1行へ統合。previewは削除。whyScienceの全文・免責は設定の「仕組み」へ移動。
- lockScreenCheck・lockThemePickはオンボーディングから削除。初回体験完了後または初回win後、ホームからロック画面の確認と既存テーマ選択へ進める。目標保存によるLive Activity自動開始は維持。iOSの「許可／許可しない」への答え方は、完了画面のボタンの上で伝える（2026-09-26・O-09参照）。
- アプリ内の一呼吸の体験（experience）はSNSで見せる。選んだアプリの中で最初のSNS（Safari以外）を使う（2026-09-26 オーナー指示「Safariを開いた時じゃなくSNSにして」）。Safariだけを選んだ人はSafariのまま（体験の「開かなかった」は本物の記録になるため、選んでいないアプリで見せると記録がずれる）。何も選んでいなければ見本のInstagram。ショートカット設定中に実際に開いたアプリで出る体験は、そのアプリのまま。
- 目標はスキップ不可。新見出しはja「SNSの代わりに何を進めたい？」／en「What do you want to make time for?」／ko「SNS 대신 무엇을 하고 싶나요?」。中央表示（設計34pt・縮小なし、収まらない場合は意味区切り1箇所で2行）。2026-09-21の短縮文言・副文の任意区切りは[UI文言集](11_ui_copy.md)の「11画面のディスプレイコピー」を参照。
- 推計の免責・回復が仮定である旨を維持。回答と目標は端末内保存。質問間のトランジションアニメーションは追加しない。
- クイズは回答を選ぶと進む。通知・自動化の延期、ペイウォールの「あとで」とS1のブロック設定延期は維持。

### O-03r Quiz Result（推計損失リビール）

目的: 回答からの推計損失を提示する感情のピーク。責めずに「取り戻せる」希望とセットで示す。

表示文言:

```text
あなたのSNS時間は

1日 約2.5時間
1年で 約38日

※ご回答からの推計値です。医療診断ではありません。

このままなら50年で 人生の約5.2年

[この時間を変える]
```

設計:

- 数値は O-02 の利用時間バケットから決め打ちの推計表（例: 2-4時間→2.5h/日→38日/年）で算出。
- 最終行は年間日数×50年÷365の単純換算。前提の50年を文中に明示する。実値より大きい数字を出さないため、1桁小数へ**切り捨てる**（四捨五入しない）。バケット別の値は 1.5 / 3.1 / 5.2 / 10.4 / 13.5 年（`LossEstimator.lifetimeYears(fromYearlyDays:)`）。
- 「あなたは依存しています」等の診断的表現は使わない（App Review/景表法・docs/09 §3）。
- 効果の約束（「38日取り戻せます」と断定）はしない。「取り戻せます」は可能性の提示に留める。

#### 人生グリッド（2026-08-22 オーナー指示）

O-03rの50年換算は、既存の免責と人生年数の行を変えず、その直下へ50年を面積で示すグリッドを追加する。

```text
※1日約2.5時間の想定にもとづく推計値です。
このままなら50年で 人生の約5.2年
[■■■■■▪□□□□]
[□□□□□□□□□□]
[□□□□□□□□□□]
[□□□□□□□□□□]
[□□□□□□□□□□]
1マス ＝ 1年　塗り ＝ SNSに消える時間
```

- 50マス固定、10列×5行、左上から行優先で1マスを1年として並べる。マス数の正本は `LossEstimator.lifetimeHorizonYears`。
- 塗る量は `LossEstimator.lifetimeYears(fromYearlyDays:)` の切り捨て済み値を使う。整数部を満マス、端数部を次の1マスの左から横幅比率で塗り、切り上げない。例: 5.2年は5マス＋次のマスの20%。
- 分解は `LossEstimator.lifeGridFill(lifetimeYears:)` に一元化し、0...50マスへクランプする。50年以上は50マス＋端数0とする。
- 表示順は disclaimer → lifetime行 → グリッド → 凡例。登場順は lifetime行=4、グリッド=5、凡例=6。通常時は約25ms/マスで左上から点灯し、Reduce Motion時は即時表示する。
- グリッドはVoiceOver上で1要素とし、個々のマスは読み上げない。キャラクターは既存の1体だけを維持し、グリッド内へ追加しない。

凡例（キー `onboarding.result.life_grid.legend`）:

| 言語 | 文言 |
| --- | --- |
| ja | 1マス ＝ 1年　塗り ＝ SNSに消える時間 |
| en | 1 square = 1 year   Filled = time lost to social media |
| ko | 한 칸 = 1년   채워진 칸 = SNS에 사라지는 시간 |

### O-04 Goal Setup（軽量目標入力）

目的: 空いた時間の「戻る先」を言語化させる。損失リビール（O-03r）で顕在化した危機感を、前向きな方向性に転換する。

表示文言:

```text
取り戻した時間で
何をしたいですか？

目標（1つだけ）
[例: 英語で仕事ができる自分になる]

ロック画面に表示する短い言葉
[例: 英語で話す]（12-16文字）

[次へ]
[あとで設定する]
```

設計:

- オンボーディングでは1件だけ入力する。完了後はFreeで1件、Proで複数件をフラットリストとして管理する。
- 例文プリセットをタップで選択可能にし、入力の摩擦を下げる。
- スキップ可。スキップ時はホーム/ウィジェット側で設定を促す。
- 追加目標はProで解放する。目標の種類分け、期限、チェックリストは設けない。
- ここで入力した目標文がLive Activity（O-08）にフル文言で表示され、短縮表示名はホームウィジェット/Dynamic Islandで使われる。

### O-05 Choose Mode

目的: 最初から厳しすぎて離脱するのを避ける。ユーザーが自分で強度を選ぶ。

表示文言:

```text
SNSを開く前の止め方

開く前の確認の強さを選びます。

[Deep Focus]
作業中はSNSを開く前に強く止める

[通常モード]
SNSを開く前にひと呼吸と理由確認

[夜だけ強める]
夜は確認を強くして開きすぎを防ぐ

[次へ]
```

デフォルト選択:

- Deep Focus。

UI:

- 3つのカードを縦並び。
- Deep FocusをRecommendedにする。
- 強制感を出さないため、通常モードと夜だけ強めるも同じ画面に残す。

### O-06 Intervention Preview

目的: どんな介入が入るか事前に見せる。機能説明ではなく、開く瞬間に選択を取り戻す感覚を伝える。

表示文言:

```text
SNSを開こうとすると、こうなります

目的を確かめて、必要なときだけ意図して開けるようにします。

1. 何のために開くか確認する
2. 仕事や連絡なら、すぐ時間を選ぶ
3. 暇つぶしなら、一呼吸して選び直す
4. 使った後の満足感を振り返る

[表示を確認する]
```

体験後のミニプレビュー:

```text
何のために開く？

[開かない]
[理由を選んで続ける]
```

UI:

- 小さなShield画面プレビューを1枚表示。
- 動画/アニメーションで、黒い一呼吸画面から青い警告画面へ遷移しても良い。
- 余裕があれば、最後に「SNSを見てどうだった？」の1画面を薄く見せる。
- ここではアファメーション、今日の一歩、複数タスク、目標管理、期限は出さない。

補足:

- iOSでは他社SNSを閉じた瞬間を直接検知できない。
- 通常のSNS起動では時間選択・時間経過通知・自動リフレクションを行わない。シールド一時解除だけ、再シールドまたはDopaBreak復帰時に振り返る。
- オンボーディングでは「閉じた瞬間に必ず質問します」とは言わない。

### O-06b Why Science（科学的背景）

目的: 「本当に効くのか」の疑念に、原理レベルの根拠で答える（信頼形成）。

表示文言:

```text
「一呼吸」の背景にある行動科学

行動科学の4つの原理を使っています。

1. 摩擦  反射的な起動に一拍置く
2. 実行意図  開く前に理由を言語化する
3. 自己モニタリング  今日何回目かを見る
4. 自己観察  見た後の満足感を記録する

開く前にワンクッション置く手法は、
査読付き研究（PNAS, 2023）で
SNS利用を平均57%減らすことが
```

### 2026-07-29 O-03r 最終行 人生年数換算への置換（オーナー指示・実装反映済み）

3言語の確定文言（キー `onboarding.result.lifetime`。旧キー `onboarding.result.ten_years` は削除済み）:

| 言語 | 文言 |
| --- | --- |
| ja | このままなら50年で 人生の約%@年 |
| en | Over the next 50 years, that's about %@ years of your life |
| ko | 이대로면 50년에 인생의 약 %@년 |

バケット対応値:

| O-02 回答 | 1日 | 年間日数 | 50年換算 |
| --- | --- | --- | --- |
| 1時間未満 | 45分 | 11日 | 1.5年 |
| 1〜2時間 | 90分 | 23日 | 3.1年 |
| 2〜4時間 | 150分 | 38日 | 5.2年 |
| 4〜6時間 | 300分 | 76日 | 10.4年 |
| 6時間以上 | 390分 | 99日 | 13.5年 |

根拠:

- **年数単位への変更**: 日数は蓄積の実感が弱い。年単位にすると失う対象が「人生そのもの」に変わり、損失回避が効く。
- **追加ではなく置換**: 同一画面に「日/年/年」と数字を3つ並べると訴求が薄まる。最終行は1つに絞る。
- **50年という前提の明示**: 文中に「50年で」と書くため、読み手が前提を検証できる。前提を伏せた「人生の約N年」は誇大表示になる。
- **切り捨て（絶対に切り上げない）**: 23日は 23×50÷365 = 3.1506… 。四捨五入なら3.2だが3.1を出す。旧「起きている人生の約1年分以上」が数値不成立で削除された経緯（本節2026-07-18 根拠）を繰り返さないため、丸めは常に控えめ側へ倒す。
- **算出の一元化**: `LossEstimator.lifetimeHorizonYears` と `lifetimeYears(fromYearlyDays:)` に集約。切り捨て済みの値を文字列化して `%@` へ渡すため、書式側で丸め直しは起きない。
