# DopaBreak オンボーディング画面設計

作成日: 2026-06-27 / 改訂: 2026-07-02（確定方針「目標ヒーロー軽量版」反映・損失顕在化クイズフローの正式化・v2モックと整合）

## 1. 方針

DopaBreakは、SNS依存を更生して人生に集中するためのアプリである。ただし、ユーザー向け文言では「依存」「更生」を強く言いすぎない。恥や罪悪感ではなく、**現実に戻る、集中を取り戻す、無意識を止める** という言葉を使う。

オンボーディングの目的は、機能説明ではない。ユーザーに以下を完了させること。

1. 自分がSNSを無意識に開いていると認識する。
2. 止めたいSNSを1つ以上選ぶ。
3. 開く前の介入がどう効くか理解する。
4. Screen Time権限を許可する。
5. 最初のブロックルールを有効化する。
6. SNSを使った後に、満足感を短く振り返る設計だと理解する。
7. 毎朝の目標通知とLive Activity（ロック画面カード）で戻る先が届くことを理解する。

## 2. 入れないもの / 入れるもの（2026-07-02 確定）

以下はアプリ全体に入れない。

- アファメーション
- 今日の一歩
- 複数タスク
- 期限
- チェックリスト
- リマインダー
- プロジェクト管理
- ビジョンボード
- 引き寄せ訴求

**入れるもの（軽量目標・確定）**: オンボーディングでは最初の目標を1件だけ任意入力できる。完了後はフラットリストとして管理し、Freeは1件、Proは複数件を保存できる。

- 種類ラベルや期限は付けず、人生の方向性を表す短い目標を1件入力する（例: 英語で仕事ができる自分になる）。
- 表示先は朝の通知/Live Activity（フル文言）・ホームウィジェット/Dynamic Island（短縮表示名）・介入時のみ。タスク管理画面にはしない。
- オンボーディングでは O-04 Goal Setup として1画面・任意入力（スキップ可・後から設定可）。

## 3. デザイン原則

### トーン

強制ではなく、冷静な自己制御。

最新モックでは、黒背景、余白、強いタイポグラフィ、直線的な計測バーで「深く集中に入る」感覚を出す。アファメーション、願望実現、潜在意識などのコピーには寄せない。円形の装飾、魔法陣のように見えるリング、神秘的な図形は使わない。

使う言葉:

- SNSを断つ
- 人生に戻る
- 無意識スクロール
- 本当に今必要ですか
- 必要なときだけ、意図して開く
- 現実に集中する
- 集中を取り戻す

避ける言葉:

- あなたは依存しています
- 意志が弱い
- 失敗
- 治療
- 願いが叶う
- 潜在意識

### ビジュアル

| 要素 | 方針 |
| --- | --- |
| ベース | 黒、チャコール、深いネイビー |
| アクセント | 静かなライム/ゴールド = Deep Focus、グレー = 計測、赤 = 注意 |
| 角丸 | 12-18px。カードは落ち着いた厚みを出す |

### 心理学的訴求

他のScreen Time系アプリを使っても続かなかったユーザーに刺すため、オンボーディングでは「制限するアプリ」ではなく「開く前の自動反応を止めるアプリ」として伝える。

| 心理原理 | ユーザーの本音 | 訴求への変換 |
| --- | --- | --- |
| 習慣ループ | 気づいたら開いている | 開く瞬間に止まる |
| 実行意図 | 開いた後では遅い | SNSを開こうとしたら一呼吸する |
| 摩擦設計 | 制限を解除してしまう | 解除より前に理由確認を入れる |
| 自己決定感 | 強制されると反発する | 自分で対象SNSと強さを選ぶ |
| 自己モニタリング | 何回開いたか自覚がない | 今日何回目かを見せる |
| 自己観察 | SNS後に満たされたか覚えていない | 見た後の満足感を記録する |
| 恥の回避 | 意志が弱いと思いたくない | 意志ではなく設計の問題として扱う |

コピーの基本方針:

- 「意志が弱い」ではなく「SNSは反射で開けるように作られている」と伝える。
- 「ブロックする」より「開く前に選択を取り戻す」と伝える。
- 「全部やめる」より「一番開くSNSから始める」と伝える。
- 「厳しく制限する」より「解除しない強さで始める」と伝える。
- 「SNSは悪い」ではなく「見た後の自分の感覚を見える化する」と伝える。

## 4. 推奨オンボーディング構成（2026-07-02 確定・損失顕在化フロー）

**14ステップ**（`output/mockups/lifefocus_v2/` と1:1対応）。所要時間は2-3分。旧7画面版は廃止し、ICP確定（SNS依存全般×損失回避訴求）に合わせ、**自己診断クイズ→推計損失リビール**で悩みを顕在化してから設定に入る構成を正式仕様とする。

| Step | ID | 画面 | 目的 |
| --- | --- | --- | --- |
| 1 | O-01 | Welcome | 損失回避の世界観（人生の時間は二度と戻らない） |
| 2 | O-02 | Self Check Q1 | 開く頻度の自己申告（端末内保存を明示） |
| 3 | O-02b | Quiz Q2 | 目的なきスクロールの頻度（PHQ型） |
| 4 | O-02c | Quiz Q3 | 「時間を溶かした」後悔の顕在化 |
| 5 | O-03r | Quiz Result | **推計損失リビール**（例: 1日2.5h→年38日）。感情のピーク |
| 6 | O-03 | Choose Apps | 止めたいSNSを選ぶ（汎用アイコン） |
| 7 | O-04 | Goal Setup | **最初の目標1件を任意入力**（スキップ可） |
| 8 | O-05 | Choose Mode | 最初の強さを選ぶ（デフォルト=Deep Focus） |
| 9 | O-06 | Intervention Preview | 開く前の体験を見せる |
| 10 | O-06b | Why Science | 科学的背景（原理レベル・医療目的でない旨） |
| 11 | O-07 | Permission | Screen Time許可を取る |
| 12 | O-08 | Notification Guide | 通知許可＋Live Activity開始（2026-07-02: 旧Widget Guideを置換） |
| 13 | O-08b | Pre-Paywall Summary | 専用プラン要約（サンクコスト形成）→ペイウォールへ |
| 14 | O-09 | Ready | 初回設定完了 |

設計原則:

- O-02〜O-03r の数値は**自己申告からの推計**。Screen Time権限前に実データは扱えないため、`※ご回答からの推計値です。医療診断ではありません。` を必ず併記する。権限取得後は実データに差し替える。
- O-03r（損失リビール）が感情のピーク。ここまでに離脱させない（各クイズはタップ1回で進む）。
- O-08b→ペイウォール(P-01)は7日無料トライアル訴求。スキップ可（ハードペイウォールにしない場合のA/B対象）。

### 各ステップの離脱対策（Activation設計）

| 画面 | 離脱リスク | 対策 |
| --- | --- | --- |
| O-02〜02c | 質問が多い | 3問固定・タップ1回/問・進捗バー表示 |
| O-03r | 数字が刺さりすぎて防衛反応 | 責め文言を使わず「取り戻せる」希望とセットで提示 |
| O-04 | 入力が面倒 | 例文プリセットをタップで選択可・スキップ可 |
| O-07 | 権限への不安 | 端末内保存・監視しない旨を許可ダイアログ前に説明 |
| O-08b→P-01 | 課金圧 | 無料で使い始められる導線を残す（Free機能明記） |

## 5. 画面詳細

### O-01 Welcome

目的: 「これは普通の時間管理アプリではなく、SNSから人生に戻るアプリ」と一瞬で伝える。

表示文言:

```text
人生の時間は
二度と戻らない

そのスクロールが、いちばん高くついている。

開く前に、選び直す

[はじめる]
```

レイアウト:

```text
┌────────────────────┐
│ 9:41               │
│                    │
│                    │
│ SNSを断つ 人生に   │
│ 戻る               │
│                    │
│ 無意識スクロールを │
│ 止めて深い集中へ   │
│                    │
│ 開く前に止まる     │
│ [はじめる]         │
└────────────────────┘
```

UI:

- 背景上部に朝焼けの海写真を置き、下部をE1黒へフェードさせる。
- 中央より少し上に大きな見出し。
- CTAは画面下部固定。
- 余計な説明や機能一覧は出さない。

### O-02 Self Check

目的: ユーザーに「このままだとまた無意識に開く」と認識させる。

MVPでは自己申告。タップだけで完了する。

表示文言:

```text
意志の問題ではありません

SNSは反射で開けるように作られています。
まず開きやすい時間を見つけます。

1日にSNSをどれくらい使っていますか

[1時間未満]
[1-2時間]
[2-4時間]
[4時間以上]

特に開きやすい時間帯は

[朝]
[昼]
[夕方]
[夜]
[寝る前]

[次へ]
```

代替: もしScreen Time権限を先に取る設計にするなら、この画面は実データ表示に変更する。

実データ版:

```text
いまのSNS習慣を確認

1日平均 3時間12分
開く回数 48回
夜の使用 1時間04分

まずは、開く前に止まる仕組みを作ります。

[次へ]
```

設計判断:

- いきなり厳しい数値を見せると刺さるが、権限前に実データは扱えない。
- 最初は自己申告で進め、権限後に「実際の記録」を出す方が審査/実装の整合性が高い（2026-07-02 確定: 自己申告先行方式を採用）。

### O-02b Quiz Q2（目的なきスクロール）

目的: 「開いた理由を説明できない時間」の存在を自覚させる。

表示文言:

```text
気づいたら、目的もなく
スクロールしていたことは？

[ほぼ毎日]
[週に数回]
[たまに]
[ほとんどない]
```

UI: PHQ型の頻度4択。タップで即次へ。進捗バーを上部に表示。

### O-02c Quiz Q3（後悔の顕在化）

目的: 損失感情を本人の言葉で選ばせる（一貫性の原理の起点）。

表示文言:

```text
SNSを閉じたあと
「時間を溶かした」と感じることは？

[ほぼ毎日]
[週に数回]
[たまに]
[ほとんどない]
```

### O-03r Quiz Result（推計損失リビール）

目的: 回答からの推計損失を提示する感情のピーク。責めずに「取り戻せる」希望とセットで示す。

表示文言:

```text
あなたのSNS時間は

1日 約2.5時間
1年で 約38日

※ご回答からの推計値です。医療診断ではありません。

この時間の使い方は
ここから選び直せます

[使い方を見直す]
```

設計:

- 数値は O-02 の利用時間バケットから決め打ちの推計表（例: 2-4時間→2.5h/日→38日/年）で算出。
- 「あなたは依存しています」等の診断的表現は使わない（App Review/景表法・docs/09 §3）。
- 効果の約束（「38日取り戻せます」と断定）はしない。「取り戻せます」は可能性の提示に留める。

### O-03 Choose Apps

目的: 止めたいSNSを選ばせる。最初は1つでも良い。

表示文言:

```text
一番開くSNSから始める

全部を一気に止める必要はありません。
まず1つだけ開く前に止まる仕組みを入れます。

[X]
[Instagram]
[TikTok]
[YouTube]
[その他のアプリを選ぶ]

[次へ]
```

UI:

- 行はアプリ名 + 汎用アイコン + チェック。
- 商用UIでは各SNSの実ロゴ使用はライセンス確認が必要。初期デザインでは汎用アイコン推奨。
- Freeプランでも最初は1つ選べる。

### O-04 Goal Setup（軽量目標入力）

目的: 空いた時間の「戻る先」を言語化させる。損失リビール（O-03r）で顕在化した危機感を、前向きな方向性に転換する。

表示文言:

```text
取り戻した時間で
何をしたいですか

目標（1つだけ）
[例: 英語で仕事ができる自分になる]

ロック画面に表示する短い言葉
[例: 英語で話す]（12-16文字）

[次へ]
[あとで設定する]
```

設計:

- オンボーディングでは1件だけ入力する。完了後はFreeで1件、Proで複数件をフラットリストとして管理する。
- 例文プリセットをタップで選択可能にし、入力の摩擦を下げる。
- スキップ可。スキップ時はホーム/ウィジェット側で設定を促す。
- 追加目標はProで解放する。目標の種類分け、期限、チェックリストは設けない。
- ここで入力した目標文が朝の通知/Live Activity（O-08）にフル文言で表示され、短縮表示名はホームウィジェット/Dynamic Islandで使われる。

### O-05 Choose Mode

目的: 最初から厳しすぎて離脱するのを避ける。ユーザーが自分で強度を選ぶ。

表示文言:

```text
SNSを開く前の止め方

開く前の確認の強さを選びます。

[Deep Focus]
作業中はSNSを開く前に強く止める

[通常モード]
SNSを開く前にひと呼吸と理由確認

[夜だけ強める]
夜は確認を強くして開きすぎを防ぐ

[次へ]
```

デフォルト選択:

- Deep Focus。

UI:

- 3つのカードを縦並び。
- Deep FocusをRecommendedにする。
- 強制感を出さないため、通常モードと夜だけ強めるも同じ画面に残す。

### O-06 Intervention Preview

目的: どんな介入が入るか事前に見せる。機能説明ではなく、開く瞬間に選択を取り戻す感覚を伝える。

表示文言:

```text
SNSを開こうとすると、こうなります

目的を確かめて、必要なときだけ意図して開けるようにします。

1. 何のために開くか確認する
2. 仕事や連絡なら、すぐ時間を選ぶ
3. 暇つぶしなら、一呼吸して選び直す
4. 使った後の満足感を振り返る

[表示を確認する]
```

体験後のミニプレビュー:

```text
何のために開く？

[開かない]
[理由を選んで続ける]
```

UI:

- 小さなShield画面プレビューを1枚表示。
- 動画/アニメーションで、黒い一呼吸画面から青い警告画面へ遷移しても良い。
- 余裕があれば、最後に「SNSを見てどうだった？」の1画面を薄く見せる。
- ここではアファメーション、今日の一歩、複数タスク、目標管理、期限は出さない。

補足:

- iOSでは他社SNSを閉じた瞬間を直接検知できない。
- 利用後リフレクションは、選択時間終了時、再シールド時、DopaBreak復帰時、通知で近似する。
- オンボーディングでは「閉じた瞬間に必ず質問します」とは言わない。

### O-06b Why Science（科学的背景）

目的: 「本当に効くのか」の疑念に、原理レベルの根拠で答える（信頼形成）。

表示文言:

```text
「一呼吸」の背景にある行動科学

行動科学の4つの原理を使っています。

1. 摩擦  反射的な起動に一拍置く
2. 実行意図  開く前に理由を言語化する
3. 自己モニタリング  今日何回目かを見る
4. 自己観察  見た後の満足感を記録する

開く前にワンクッション置く手法は、
査読付き研究（PNAS, 2023）で
SNS利用を平均57%減らすことが
示されています。

※他社アプリ(one sec)を対象とした研究です。
※本アプリの効果を保証するものではありません。
※医療・治療を目的としたアプリではありません。

[次へ]
```

設計:

- 研究数値は必ず出典（PNAS 2023 / Max Planck）と「一般手法への言及」であることを明記する（docs/09 §2 の表現ルール準拠）。
- 「科学的に証明されたアプリ」という自称はしない。

### O-07 Permission

目的: Screen Time権限を許可してもらう。

表示文言:

```text
SNSの前で止める許可

iOSのScreen Timeを使います。

選んだSNSの前に表示します。
使用データはデフォルトで端末内に保存されます。
通知やタスク管理はしません。

[許可して始める]
[あとで]
```

補足:

- 「なぜ必要か」を明確にする。
- 「監視される」不安を下げる。
- `あとで` は残すが、機能制限があることを次画面で説明する。

### O-08 Notification Guide（戻る先が毎日届く・2026-07-02改訂）

目的: 通知許可とLive Activity開始をオンボ内で完了させる（Activation条件）。旧Widget Guide（手動設置が必要＝離脱要因）を置換。

表示文言:

```text
ロック画面に、戻る先を

朝の通知とLive Activityで、
目標を毎日思い出します。

[プレビュー: 目標文＋「今日 N回 開かずに戻れた」]

[通知をオンにする]
[あとで]
```

設計:

- O-04で入力した目標文をそのまま通知カードのプレビューに表示する（未入力なら例文）。
- [通知をオンにする] → UserNotifications許可ダイアログ → 許可後にデイリーLive Activityを自動開始（手動設置ゼロ）。
- 「あとで」を選んだユーザーには、初回介入成功後に再案内する。
- テーマはFree=E1。テーマ変更導線はPro（設定→ロック画面の表示）。

### O-08b Pre-Paywall Summary（専用プラン要約）

目的: ここまでの入力（アプリ数・目標・推計損失）を「あなた専用のプラン」として再提示し、サンクコストと保有効果を作ってからペイウォールへ渡す。

表示文言:

```text
あなたのプランができました

止めるアプリ      Instagram ほか2件
戻る先            英語で話す
取り戻せる時間    年 約38日分

このプランで始めますか

[プランを有効にする]
```

設計:

- 数値・項目はすべて本人の入力の再掲。新しい約束はしない。

### ロック画面表示のルール（O-08の補足・2026-07-02改訂）
