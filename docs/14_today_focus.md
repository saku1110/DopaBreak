## 0. 決定の経緯（2026-07-09 オーナー議論）

検討した3案と結論:

| 案 | 内容 | 判定 |
| --- | --- | --- |
| A: 階層化 | 大目標→月目標→日タスクの階層 | ❌ 却下。月目標が陳腐化→介入面に古い情報→馴化。維持コストが継続率を殺す |
| B: Todo統合 | Todo管理機能を内蔵 | ❌ 却下。Todoアプリと競合・未消化タスクが罪悪感リスト化・ウェルビーイングから生産性へポジションがブレる |
| C: フラット自由記述のみ | 現行確定のまま | △ 維持コスト最小だが静的表示→馴化で介入効果が減衰 |
| **採用: C＋今日の1つ** | フラット目標（複数）＋「今日の1つ」（常に1枠） | ✅ 下記 |

**確定事項:**
1. 目標はフラットな複数リストのまま（2026-07-08確定を維持。階層化しない）
2. 「今日の1つ」= **SNSを見ない時間で何をするかを1行で宣言する枠。常に1つだけ**
3. 完了チェックあり・**片側集計**（できた日だけ記録。未完了は数えない・表示しない・責めない）
4. ストリーク（連続記録）は**採用しない**

## 1. 仕様

### 1.1 「今日の1つ」の枠

| 項目 | 仕様 | 理由 |
| --- | --- | --- |
| 件数 | 常に1枠のみ | 一呼吸の画面は2〜3秒。選択肢が複数あると選択回避で「結局SNS」に流れる（choice overload / goal dilution） |
| 入力 | 任意。未入力でもアプリは完全に機能 | 義務化は離脱要因。Foggモデル=簡易性優先 |
| 失効 | 毎日0時に自動失効。**繰り越しなし** | 古い情報が一呼吸に出続けると馴化。未達の山=罪悪感リスト化を構造的に防ぐ |
| 差し替え | 完了後は同日内に次を書ける（枠は1つのまま中身を入れ替え） | 小さな勝ちの連鎖。ただしTodoリスト化はしない |
| 文字数 | 短文（ロック画面1行に収まる長さ。目標のロック画面用短縮名と同等の制限） | Live Activity表示面の物理制約 |
| フレーミング | 「〜しない」ではなく「〜する」（接近目標）を促すプレースホルダ・例文 | 皮肉過程理論（抑制目標は失敗しやすい）。実装意図=if-then の then に入る具体行動 |

### 1.2 表示優先順位（一呼吸S-03・Live Activity共通）

```
今日の1つ あり → 最上部に「今日の1つ」を主役表示 ＋ フラット目標を下に小さく
今日の1つ なし → フラット目標を箇条書き表示（既存仕様のまま＝フォールバック）
```

- 大目標（なぜ）＋今日の1つ（代わりに何を）の同時表示が原則。解釈レベル理論（抽象=誘惑抵抗）と実装意図（具体=行動転換）の両取り。
- Live Activityは面積制約上、実表示は「今日の1つ」1行＋目標短縮名1〜2行を上限とする（doc12「全目標表示」はこの制約内での運用と読み替える）。

### 1.3 完了チェック（片側集計）

- チェックを付けられるのは本人のみ。付けた日だけ FocusLog に記録
- **未完了は記録しない・件数化しない・UI に「未達成」系の表示を出さない**（できた日だけ光る）
- 統計・週次レポートに「開かずに我慢した」と並べて「代わりにやれたこと」を追加（取り戻した時間の使い道=アプリの価値証明）
- 翌日は常に白紙スタート（fresh start効果。途切れの概念自体が存在しない）

### 1.4 入力導線

1. ホーム画面の最上部に入力枠（未入力時のみ促し表示）
2. 一呼吸の勝ち画面（「開かなかった あなたの勝ち」）の後に未入力なら軽く促す（スキップ可・1日1回まで）

### 1.5 依存させにくい設計のガードレール（本機能に適用）

- ストリーク・連続日数バッジ・損失回避型の演出は禁止（SNSと同じエンゲージメント構造になり思想がブレる）
- 未入力・未完了への通知リマインドは送らない
- 片側集計を崩す変更（未達表示・達成率%など）はオーナー承認なしに入れない

## 2. データモデル・実装方針（Codex委譲時の指針）

- Core新規 `TodayFocus`: `text: String` / `dateKey: String`（端末タイムゾーンのYYYY-MM-DD） / `completedAt: Date?`
- 保存: App Group（GoalStore/RuleStoreと同パターン・Extension読み取り可）。`LockSurfaceState` スナップショットに `todayFocusText` を追加しLive Activity/通知面が読む
- `FocusLog`: 完了時のみ append（date, text）。StatsService週次サマリーに完了件数を追加
- 純粋ロジック（日付失効判定・片側集計）はCoreでテスト100%（既存の品質ゲート踏襲）
- 分析イベントは件数のみ。**今日の1つの本文は端末外へ送らない**（既存プライバシー方針doc05 §に準拠）

## 4. 学術的根拠（要約）

| 設計判断 | 根拠 |
| --- | --- |
| 具体的な代替行動を1つだけ提示 | 実装意図（Gollwitzer, meta d≈0.65）。if-thenは単一の具体行動で効果最大・複数で希釈 |
| 大目標＋今日の1つの同時表示 | 解釈レベル理論（Trope & Liberman: 抽象=なぜ、が誘惑抵抗を高める）×実装意図（具体=何を、が行動を変える） |
| 「〜する」フレーミング | 皮肉過程理論（Wegner: 抑制目標は逆効果）→接近目標への置換 |
| 毎日失効・白紙スタート | 馴化（habituation）防止。one sec効果検証（Grüning et al. 2023, PNAS）でも介入の新鮮さが効果維持に寄与 |
| ストリーク不採用・片側集計 | 自己決定理論（外発的コントロール・損失回避型エンゲージメントの回避）＋fresh start効果（Milkman） |
| 1枠のみ・入力任意 | choice overload / Fogg行動モデル（簡易性） |

## 5. 検収基準（v1.1実装時）

オーナー実機で: ホーム→今日の1つ入力→対象アプリタップ→一呼吸S-03に「今日の1つ」が主役表示→[開かずに戻る]→勝ち画面→完了チェック→統計・週次レポートに「代わりにやれたこと」反映。未入力日はフラット目標フォールバック表示、翌0時に自動失効、が確認できること。
