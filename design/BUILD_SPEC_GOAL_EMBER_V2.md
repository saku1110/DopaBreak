# BUILD SPEC: 目標設定画面の種火 v2（知覚できる成長）

対象: `ios/DopaBreak/OnboardingMotion.swift` の `GoalEmberField`、および `ios/DopaBreak/OnboardingFlow.swift` の `onboardingBackdrop` / `goalEmberGrowth`。

## 背景（なぜ直すか）

v1（2026-07-25実装）は「目標を入力するほど種火が育つ」という設計だった。
実測キャプチャ `output/screenshots/goal-ember/01-ember-empty.png`（intensity 0.12）と
`03-ember-max.png`（0.55）を並べても、**炎の大きさ・明るさの差がほぼ知覚できない**。

原因は3つ。

1. 可変幅が intensity 0.12〜0.55 の 0.43 しかなく、シェーダ側で intensity が効くのは
   `flameHeight = mix(0.50, 0.78, intensity)` と `baseWidth = mix(0.120, 0.215, intensity)` のみ。
   0.43 の幅では高さ・幅とも 12% 程度しか動かない。
2. 描画枠が 320×172 で固定。**物理的な大きさが一切変わらない**。
3. 変化にアニメーションが乗っていない（暗黙アニメは linear 1/30 秒）。動きとして知覚されない。

さらに、黒背景に炎が1個だけ浮いており、入力欄との因果が視覚的に読めない。

オーナー判断（2026-08-06）: **まず「見えるようにする」改修を行い、それでも微妙なら種火を削除する。**

## 変更内容

### 1. 枠のサイズを成長させる（最大のレバー）

`GoalEmberField` の固定枠 `maxWidth 320 / height 172` を、成長に応じた補間へ変更する。

| | growth = 0（種火） | growth = 1（上限） |
|---|---|---|
| 幅 | 200 | 340 |
| 高さ | 104 | 224 |

枠が拡大すればシェーダの正規化空間ごと拡大するため、炎そのものが大きくなる。

### 2. intensity のレンジを広げる

現行 `0.12 + growth * 0.43`（0.12〜0.55）を **0.10 + growth * 0.62（0.10〜0.72）** に変更する。

- 下限を下げる: 未入力は「まだ灯っていない種火」として明確に弱く
- 上限を上げる: ただし介入画面のピーク 1.0 には届かせない（**炎の聖域は維持**）

### 3. 立ち上がりを早くする

`goalEmberGrowth` は現行 `min(count / 12.0, 1.0)` の線形。
これを **`pow(min(count / 12.0, 1.0), 0.65)`** にイージングする。
1〜2文字目から目に見えて動くようにするため。上限到達は12文字のまま変えない。

### 4. 成長をアニメーションさせる

growth 由来の intensity・枠サイズの変化に `.easeOut(duration: 0.42)` を当てる。
1文字打つたびに「ふわっと育つ」動きが出ることが、この仕掛けの本体である。

注意: `FlameBreathView` 内部の `.animation(.linear(duration: 1.0/30.0), value: breathPhase)` は
シェーダのフレーム同期用なので触らない。アニメーションは `GoalEmberField` 側で
`withAnimation` または `.animation(_:value:)` により付与する。

### 5. 足元のグロー（浮遊感の解消）

炎の背面・画面下端に、幅いっぱいの楕円グローを1枚追加する。

- 色: シェーダの `rootGlowColor` に合わせた暖色（おおよそ `Color(red: 0.92, green: 0.075, blue: 0.001)`）
- 不透明度: growth 0→1 で 0.05 → 0.18
- ぼかし半径: **86 固定**。growth 0→1 の 44→86 は縦の `scaleEffect`（0.512→1.0）へ置き換える
  （理由: 半径86ptのぼかしを成長中フレームごとに再ラスタライズすると重い。
  ぼかし結果を `compositingGroup` で一度平坦化し、以降は変換と不透明度だけを動かす。2026-08-06変更）
- 高さ: 枠高さの 0.55 倍程度（123.2pt 固定）。横は画面幅いっぱい
- 合成: `.blendMode(.plusLighter)`
- 描画上限に当たる場面では、**ぼかしの滲みを含めた実効高さ**（楕円123.2pt＋滲み103.2pt＝226.4pt）が
  上限を超えないよう縦倍率を頭打ちにする。滲み量は実測で半径の約1.2倍（2026-08-08追加）

これで「黒背景に炎が1個浮いている」から「画面の下端が温まっている」へ変わり、
炎が画面と地続きになる。

### 6. フレアを大きくする

プリセット選択時の `pulseToken` フレアは現行のキーフレーム
（`CubicKeyframe(1.0, duration: 0.18)` → `CubicKeyframe(0.0, duration: 0.62)`）を維持する。
加えて **フレア中は枠サイズを最大 +12% スケール**させ、吹き上がりを大きさでも見せる。

### 7. キーボード表示時の破綻回避

この画面はテキスト入力が主役で、成長の大半はキーボードが出ている最中に起きる。
CTA は `safeAreaInset(edge: .bottom)` でせり上がるため、種火の描画領域が圧縮される。

- キーボード表示中に炎が潰れないこと（幅を巻き込んだ等方縮小をしない）
- 利用可能高さが不足する場合は、枠高さだけを利用可能高さへ合わせて縮める。
  幅は `targetWidth` のまま伸ばす（等方に縮めると高さが張り付いた後に幅が細くなり、成長が反転して見える）
- **下限130ptを割る狭さでは描かない**。130〜170ptは形が保てないため不透明度で線形に引き、
  170pt以上で不透明度1へ戻す（2026-08-06変更。「クリップさせない」だけでは、
  SE相当の狭さで炎が入力欄カードの背面に挟まり、カードの上下に破片が覗く壊れた見え方になった）
- 炎とグローは同じ係数で引く。片方だけ残らないようにする
- 炎の頭は、不透明な背景を持つ入力欄・プリセットチップとの**重なりを許容する**。
  予約量は200ptで、背景を持たない見出しの可読性だけを守る（2026-08-06変更）。
  実測（2026-08-08・iPhone 16 Pro・最も詰まった描画状態）では炎の先端が入力欄カードの上端を
  22〜26pt 越えるが、カードは不透明なので文字の可読性は損なわれない

## 不変条件（絶対に壊さないこと）

- `ios/DopaBreak/FlameBreathView.swift` と `ios/DopaBreak/Shaders/Flame.metal` は**無変更**。
  依存もファイルも増やさない
- Reduce Motion 時は種火を出さない（`OnboardingFlow.onboardingBackdrop` の現行条件を維持）
- `allowsHitTesting(false)` / `accessibilityHidden(true)` を維持
- `framesPerSecond: 30` / `animatesFlare: false` を維持（常時描画の負荷抑制）
- intensity の上限は 1.0 未満を維持（介入画面のピークを侵さない）
- 種火が出るのは `step == .goalSetup` のときだけ

## 受け入れ基準

**empty と max のキャプチャを並べたとき、炎の大きさの差が一目でわかること。**
これを満たさない場合、この改修は失敗であり種火は削除する。
