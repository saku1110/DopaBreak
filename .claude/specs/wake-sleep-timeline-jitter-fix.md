# 起床・就寝タイムライン ドラッグ挙動の是正（バグ修正のみ）

## 症状（オーナー報告 2026-09-01）
「就寝時間とか起床時間の設定時にバーが動いた時数値が変にブレる動きがして気持ち悪い」

## 再現済みの原因（swiftで実測済み・推測ではない）

### 原因1: `snapped()` が 24:00 を越えて 0:00 へ巻き戻る
`WakeSleepTimelinePolicy.snapped(_:)` は `Int(step.rounded()) * stepMinutes` の後に
`normalized()` を通すため、23:53 以降が 1440 → 0 へ折り返す。

実測（trackWidth=300）:
```
x=298.0  raw=23:50  snapped=23:45
x=299.0  raw=23:55  snapped=00:00   ← 右端でハンドルが左端へ瞬間移動
x=300.0  raw=23:59  snapped=00:00
```
トラック右端の約1pxで、ハンドルが右端から左端へ飛ぶ。指を少し戻すと 23:45 に戻るため、
右端付近で 23:45 ⇄ 0:00 を往復して「ブレる」。
`latestMinute`（= 1425 / 23:45）が定義済みなのに未使用で、本来の意図が適用されていない。

### 原因2: `clampedMovingTime()` が最小間隔ゾーンで反対側へ2時間テレポートする
禁止ゾーン（固定ハンドルの±60分）に入ったとき、`circularDistance` で
「近いほうの境界」へ寄せるため、候補が固定ハンドルを1分でも跨いだ瞬間に
`fixed-60` から `fixed+60` へ飛ぶ。

実測（就寝23:00固定・起床ハンドルをドラッグ）:
```
提案=22:45  結果=22:00
提案=23:00  結果=00:00   ← 2時間ジャンプ。画面上はトラックを端から端まで飛ぶ
```

上記2つが重なり、22:00〜0:00 の帯で数値とハンドルが激しく飛ぶ。

## 修正方針

### 修正1: `snapped(_:)` は巻き戻さずクリップする
- 15分丸めの後、`0...latestMinute`（0:00〜23:45）へ **クランプ**する。`normalized()` による折り返しを廃止。
- 左端も右端も対称に止まること（左は 0:00 で停止、右は 23:45 で停止）。

### 修正2: `clampedMovingTime` は「いま居る側」に留める（最近傍で選ばない）
- `clampedWake` / `clampedBed` に **現在値（ドラッグ開始側の確定値）を渡す引数を追加**する。
- 禁止ゾーンに入ったら、`current` が固定ハンドルの時計回り側（`clockwiseDistance(from: fixed, to: current) <= 720`）なら `fixed + 60`、そうでなければ `fixed - 60` へ止める。
- これによりドラッグ中にハンドルが相手を飛び越えない（一般的な2ハンドルレンジスライダーの挙動）。
- **時刻ピッカー経由の交差は従来どおり可能**にする（60分以上離れた時刻を選べば通る現行動作を壊さない）。夜勤想定の「起床17:00／就寝9:00」が設定できる状態を維持すること。
- 呼び出し側 `SettingsView.updateTimeline` は `current` に現在の確定値（`wakeTimeMinutes` / `bedTimeMinutes`）を渡す。

## 触ってはいけないもの（既存裁定の維持）
- 夜専用の時間帯設定UIを新設しない。就寝・起床を唯一の情報源にする（design-decisions.md:298）。
- Date↔分の変換は成分ベース（`date(bySettingHour:minute:second:of:)`）を維持する。`startOfDay + 分加算` へ戻さない（DST日に±1時間ずれる。design-decisions.md:300）。
- `NightWindowPolicy` / `NightShieldScheduler` / MonitorExtension の夜境界検算構造は変更しない。
- タイムラインの見た目（バー・ハンドル・ラベル行・ポップオーバー）は変更しない。**今回は挙動のバグ修正だけ**。
- ドラッグのジェスチャ管理（gestureID・failsafe・tap guard・250msシールド同期デバウンス）の構造は維持する。
