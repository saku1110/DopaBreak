# 利用中の再介入 — 2026-09-05

オーナー指示: 「利用中の再介入は入れてください。使う時間を選択した上で介入入れる？ その場合、現在のSNSを使った満足度質問はいつ表示する？」

## 採用した体験

1. 設定 > 一呼吸 > 利用中の再介入で、対象SNSをScreen Timeの同じアプリ1つに接続する。カテゴリ/Webサイト/複数アプリ選択は不可。既存の一呼吸対象だけを接続できる。新しいPro制限は足さない。
2. 既存の一呼吸・理由選択を経て、5/10/15/30分から利用時間を選ぶ。監視の開始が成功してからSNSを開く。
3. iOSのDeviceActivityEventが新しい計測開始後の利用時間を累計し、閾値到達でそのSNSを専用のManagedSettingsStoreで遮蔽する。途中でSNSを閉じても時間枠をリセットしない。再オープン時に壁時計ベースの偽の「残り○分」を表示しない。
4. DopaBreakへ戻った時、既存の満足度質問を一度だけ表示する。回答またはスキップ後、「ここで終わる」「一呼吸して時間を追加」を表示する。追加は再度呼吸→時間選択。最初の理由質問を重ねない。
5. 期限前に終える場合、再介入設定の「ここで終了して振り返る」から同じ質問へ進む。SNSを閉じた瞬間の検出や、他アプリの上への独自質問画面の自動表示は実装していない。
6. 接続済みの利用は、従来の「選んだ時間後」の壁時計通知・質問を予約しない。未接続の利用は既存動作を維持する。再介入通知は既存の振り返り通知設定に従う。

Live Activityは現状維持。「1日8時間見られれば十分」というオーナー判断を採用し、常設Widgetへの置換・24時間表示の新規実装を行わない。以前の競合監査にある常設Widget提案は必須事項から外す。

## 実装と制約

- Core `Services/ReinterventionStore.swift`: アプリと拡張が共有するセッション、接続先、閾値到達、振り返りID。flockでプロセス間の状態更新とシールド再計算を直列化。各回UUIDのイベント名で古いコールバックを無効化。
- `DopaBreak/ReinterventionScheduler.swift`: 接続されたアプリ1つのDeviceActivityEvent、`includesPastActivity: false`。進行中の予算を再登録してリセットする操作は拒否。開始失敗はSNSを開かずエラー表示。追加開始失敗時は以前の到達済みセッションを維持。
- `Shared/ReinterventionShield.swift`: 再介入だけのストア `dopabreak.reintervention`。複数アプリの到達済み集合を適用し、1つの終了で他アプリを解除しない。睡眠・毎週・手動ブロックは独立して残る。
- `AppContainer.swift` / `InterventionFlowModel.swift` / `RootTabView.swift` / `PostUseReflectionSheet.swift`: 到達した振り返りだけを提示。回答済みの回を再起動後に再質問しない。保存失敗時は回答操作を再試行できる。期限切れ、対象削除、権限取消、データ削除時に後始末。
- `ReinterventionSettingsView.swift` / `InterventionFlowView.swift`: 初回の1アプリ接続、接続解除、時間選択時の再介入説明、途中終了の導線。日英韓に対応。
- MonitorExtensionは到達状態とシールドを更新し、通知設定が有効なら通知する。ShieldConfig/ShieldActionはiOS 26.5以降の`openParentalControlsApp`を利用。それより前は閉じるボタンと、通知/ホーム画面からDopaBreakを開く案内。
- 利用セッションは最長12時間。閾値未到達のまま放置した計測と、戻らず放置した再介入ブロックが永久に残らない設計。終了境界はDeviceActivityと合わせて分単位へ切り下げる。延長は新しい回になる。
- 再介入設定はiOS 17.4以降。アプリ全体の最低OSは17.0を維持。
- iOSのアプリトークンは不透明なので、Instagramのカタログ項目に本当にInstagramを選んだかの完全な自動検証はできない。1件制約、重複接続拒否、自己アプリが判別できる場合の拒否と説明で補う。
- 取得しているのは利用時間が閾値に達したというコールバック。秒単位の現在値、実利用時間レポート、常時更新される残り時間表示を追加したわけではない。OSの配信遅延や暗黙に関連ドメインを含める集計仕様があるため、秒ぴったりのアプリ単独ストップウォッチとは主張しない。
- カテゴリによる完全ブロックが併存している場合、ShieldActionだけではそのアプリのカテゴリ所属を復元できないため、親アプリ起動ボタンを控えめに抑制する。通知またはホームから戻れる。完全ブロックの解除はしない。

## 既存の週次予定の変更

再介入の8カタログ分の監視枠を確保するため、週次予定は「選択曜日ごと最大14本」から「毎日1本×2予定、拡張のCore判定で曜日照合」に変更。手動1＋就寝1＋週次2＋再介入8＝最大12本。過去の曜日活動名14本も停止対象に残し、更新時に掃除する。予定の曜日・時刻・権利・併用設定は維持。部分失敗時は登録できなかった予定だけを適用用Snapshotから除外する。以前のspecの最大16本設計を置き換える。

### 必要な利用への配慮（2026-09-05・オーナー承認により変更）

- 仕事・調べもの・連絡・投稿は、時間選択画面の「今回は利用時間を決める」が初期OFF。主ボタンは「時間を決めずに開く」。ONにすれば既存の5/10/15/30分を選択し、接続済みなら再介入する。暇つぶし・なんとなくは既存の時間選択を維持。
- OFFの回は既存Core `recordUntimedOpen()`で開いた事実と理由だけを記録。架空の利用時間・閾値監視・満足度の自動質問を作らない。新たな長時間の通過許可を保存せず、次のSNS起動時は通常の確認へ戻る。接続設定は保持する。
- 再介入後の満足度画面と終了/延長画面の両方に「必要な用事のため今回は再介入せず続ける」を追加。未回答ならスキップとして保存し、そのSNSの再介入セッションだけ終了。1回のSNS起動へ案内する。ルーティング有効期限60秒は画面要求の鮮度で、利用時間の制限ではない。残り60秒/1分とは表示しない。
- 通常の時間追加は引き続き呼吸→時間選択。必要な用事の継続では呼吸や満足度回答を強制しない。手動・週次・就寝の別ストアは解除しない。
- 変更: `InterventionFlowModel.swift`、`InterventionFlowView.swift`、`AppContainer.swift`、`PostUseReflectionSheet.swift`、ja/en/ko xcstringsと関連テスト。新しいCoreデータ形式や課金境界は追加しない。

### 目的別の通知・ブロック（2026-09-05・直前の初期OFF案を更新）

オーナー指摘「仕事していたと思ったらずっといじってしまう」を受け、仕事・調べもの・連絡・投稿も時間選択を初期ONへ戻した。必要な利用は選択時間に確認通知「まだ用事の途中ですか？」を出し、強制ブロック/満足度質問は出さない。Screen Time接続済みなら累積利用の閾値、未接続なら起動からの経過時間で通知する。この違いは画面と通知文に明記。通知にはOS通知許可と既存の「振り返りの通知」設定が必要。

- 接続済みの必要な利用は「時間になったらブロックする」を任意でONにできる。暇つぶし・なんとなくは従来のブロック型再介入。時間を決めない選択肢と、再介入からその回だけ継続する選択肢も維持。
- ReinterventionSessionに後方互換のoptional `blocksAtLimit` を追加。旧版でフィールドなしはブロック型。通知型では `shouldShield` が常にfalse、ReflectionLogは作らず、選択時間と利用理由だけをAttemptLogに保存。終了後の延長/満足度UIも出さない。
- 確認通知のIDはSNS単位の `dopabreak.workcheckin.*`。満足度通知と別にし、タップ先をreflectionへルーティングしない。新しい利用/制限なしへの変更/通知OFF/データ削除で不要な予約を取り消す。通知型セッションの到達後はアプリ復帰時に後始末。
- 実機の累積利用計測と通知配信はOSに依存し、配信遅延や集中モードの抑制があり得る。OS通知を許可していない場合も通知されるとは案内しない。
